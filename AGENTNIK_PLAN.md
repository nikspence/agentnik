# Agentnik roadmap

This is the forward-looking roadmap. For delivered behavior and operational limits, see the [README](README.md) and its linked guides. For evidence and outstanding validation, see [validation](VALIDATION.md). Previous milestones and release history remain available in Git.

## Current direction

Agentnik is an interactive client for chat, research and coding across existing model connections. The desktop app remains supported, and a terminal interface for Code is the highest development priority. Code uses one selected model, with bounded same-model subagents, user-directed goals and steering. System One remains available for optional shell-command advice. Agentnik does not provide a Decision query builder, messaging integration or multi-agent orchestration.

Preserve existing connections, sessions, attachments and credentials; keep network work off the UI thread. Do not infer model capability from endpoint or protocol compatibility. Research and coding are previews. Reopening a session does not resume requests or replay uncertain actions.

## Priorities and acceptance gates

1. **Agentnik Code in the terminal (internal codename: hawktui).** Ship the TUI first as `agentnik code`. Start in the invoking directory, including folders without Git, with an optional explicit project path. The terminal package must work without a display or Qt. Provide multiline input, prompt history, slash command discovery, streaming, tool activity, review and approvals, cancellation, and explicit session resume.
   - **SSH-only setup.** Provide interactive terminal screens or commands for all settings as part of terminal delivery. Inventory desktop settings and cover connections, credentials, models, permissions, limits, TLS, MCP, Skills, search, and other settings without needing the GUI. Settings for desktop-only features can be managed from the terminal even when the feature itself needs a desktop. Reuse shared validation and storage where practical. A config file may be supported for provisioning, but users should never have to edit one by hand. Keep credentials in the existing credential flow.
   - **Shared Code layer.** Extract run setup, session state, event delivery, approvals and cancellation behind a UI-independent interface that the desktop and terminal can share. Preserve existing data and connection compatibility. Keep a VS Code extension on the roadmap as a later client of that interface. Start with an integrated terminal launcher when useful, and consider a local process protocol for native diffs, approvals and editor context as extension work begins.
   - **Acceptance.** From a fresh account on an SSH-only machine, configure a connection and its credentials, choose a model, open a folder, review an edit or command, cancel a run, change settings, and explicitly reopen history without a GUI or manual config edits. Verify terminal behavior on Windows, macOS and Linux, including interrupted runs without automatic replay. Use offline fixtures first and qualify live model combinations separately with authorization.
2. **Reliability and compatibility.** Continue testing long coding runs, streaming and continuation, model tool-call recovery, goal and per-step limits, steering, and cancellation. Qualify provider/model/protocol combinations only with explicitly authorized requests. Report unknown usage and uncertain outcomes; do not silently replay submissions or tool calls.
3. **Platform and release qualification.** Windows clean-machine testing is complete per the user; record its build and workflow scope when available. Qualify remaining native workflow details, including credentials, TLS, accessibility, cancellation and frozen-app behavior. Qualify macOS and Linux independently. Complete bundled-license review and signing before claiming those gates. Build-host startup alone is not clean-machine validation.
4. **Localization.** Expand and review the Korean preview before advertising broader coverage. Extract application-owned strings through Qt's translation workflow, preserve user/model content and stored identifiers, and check layout, accessibility, font fallback and packaged catalogs. Preview catalogs are available for Spanish, French, Simplified and Traditional Chinese, and German. The new catalogs are machine-translated starting points and require human review, including safety-sensitive wording and regional usage, plus platform checks. Prioritize that review in the listed order before adding other languages.
5. **MCP and Skills.** Qualify more real servers and platforms. Add MCP 2026-07-28 support while preserving supported 2025 sessions. Remote HTTPS and local stdio try 2026 discovery first with legacy fallback. Continue additional multi-round-trip input and broader compatibility qualification. Local and remote 2026 task execution is experimental. Supported 2026 and 2025 form input and 2026 and 2025-11-25 HTTPS URL input are user-reviewed and continue only after an explicit response. For 2025 URL-elicitation-required errors, users review URLs and explicitly choose whether to retry. OAuth supports pre-registered and dynamically registered public clients; an Agentnik-hosted client metadata document and real-provider qualification remain. 2025 task-augmented input requests, broader content types and expanded Chat support need separate design and tests; related input for an active task is supported. Experimental task-required execution on local and remote servers waits for a final result within the operation deadline; a stopped task may continue on its server. Keep server output and skill instructions untrusted, bound resources and credentials, and preserve the current disclosed MCP permissions. Skills never grant permissions by themselves.
6. **Spec & Plan interoperability.** Keep Agentnik's documented track format and user-reviewed reconciliation. Any future Conductor support starts with a read-only adapter and fixtures from a pinned upstream revision; import/export or writes require lossless round-trip and conflict tests. Do not claim plugin compatibility from a similar workflow.
7. **Image generation.** Chat and Code have an optional image generation and editing tool using a separately selected connection and model, including OpenRouter and configured compatible passthroughs. Continue qualifying text-model tool calling, end-to-end GUI workflows, image editing, cancellation and additional providers with explicitly authorized tests. Generated images are not automatically inspected by the text model. See [validation](VALIDATION.md) for scoped live observations.
8. **Computer use.** Add an optional, user-directed Code tool for controlling a visible browser, followed by native desktop support. Start with browser navigation, page inspection, screenshots, clicks, typing and scrolling through an Agentnik-owned function-calling interface; consider provider-specific adapters separately. Reuse image input for vision-capable models, and expose page structure where available. Require explicit enablement, show the controlled target and action activity, disclose when screenshots leave the device, and let cancellation or steering stop further actions. Design confirmation for consequential actions, handle focus, display scaling and stale screen state, and never automatically replay uncertain actions. Validate with a fake backend and authorized live browser tasks before qualifying models and platforms; desktop support needs separate OS permission and compatibility testing.
9. **Web extraction.** Improve bounded public HTML retrieval with structured Markdown, main-content selection and conservative fallbacks. Preserve useful headings, links, lists, code and tables, attribution and truncation. Continue improving malformed-page handling, character encoding and extraction quality using offline fixtures; explicitly identify pages that need JavaScript when evidence permits. Evaluate optional browser rendering separately, with public-address enforcement for every request, resource limits and no bypass of access restrictions. Qualify extraction against diverse pages before claiming broad compatibility.
10. **Future enhancements.** Consider goal-wide token limits only with an explicit policy for missing provider usage, estimates and enforcement. Longer test jobs, richer diagnostics, symbol navigation, broader document analysis and stronger process isolation require separate bounded designs.

## Research and safety boundaries

Managed research and hosted search have bounded routing, explicit opt-in and conservative fallback. Preserve public-address checks, provider disclosures, source attribution and access restrictions. Never bypass blocks or infer a provider's support from a model listing. Computer use is a future, user-directed Code capability and is not currently implemented. Arbitrary research execution, autonomous background tasks and automatic provider failover remain outside the current scope.

For each change, inspect the implementation and relevant guide, preserve user data, test meaningful failure and cancellation paths, and distinguish offline mocks, native checks and authorized live evidence. The development and release commands are in [development and builds](DEVELOPMENT_VALIDATION.md).
