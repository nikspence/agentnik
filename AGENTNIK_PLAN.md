# Agentnik roadmap

This is the forward-looking roadmap. For delivered behavior and operational limits, see the [README](README.md) and its linked guides. For evidence and outstanding validation, see [validation](VALIDATION.md). Previous milestones and release history remain available in Git.

## Current direction

Agentnik is an interactive desktop client for chat, research and coding across existing model connections. Code uses one selected model, with bounded same-model subagents, user-directed goals and steering. System One remains available for optional shell-command advice. Agentnik does not provide a Decision query builder, messaging integration or multi-agent orchestration.

Preserve existing connections, sessions, attachments and credentials; keep network work off the UI thread. Do not infer model capability from endpoint or protocol compatibility. Research and coding are previews. Reopening a session does not resume requests or replay uncertain actions.

## Priorities and acceptance gates

1. **Reliability and compatibility.** Continue testing long coding runs, streaming and continuation, model tool-call recovery, goal and per-step limits, steering, and cancellation. Qualify provider/model/protocol combinations only with explicitly authorized requests. Report unknown usage and uncertain outcomes; do not silently replay submissions or tool calls.
2. **Platform and release qualification.** Windows clean-machine testing is complete per the user; record its build and workflow scope when available. Qualify remaining native workflow details, including credentials, TLS, accessibility, cancellation and frozen-app behavior. Qualify macOS and Linux independently. Complete bundled-license review and signing before claiming those gates. Build-host startup alone is not clean-machine validation.
3. **Localization.** Expand and review the Korean preview before advertising broader coverage. Extract application-owned strings through Qt's translation workflow, preserve user/model content and stored identifiers, and check layout, accessibility, font fallback and packaged catalogs. Preview catalogs are available for Spanish, French, Simplified and Traditional Chinese, and German. The new catalogs are machine-translated starting points and require human review, including safety-sensitive wording and regional usage, plus platform checks. Prioritize that review in the listed order before adding other languages.
4. **MCP and Skills.** Qualify more real servers and platforms. Add MCP 2026-07-28 support while preserving supported 2025 sessions. Remote HTTPS supports 2026 discovery and ordinary calls after an unsupported legacy-initialization error or HTTP 400, 404 or 405; local stdio also probes servers that do not promptly answer it. Complete modern-first era negotiation, 2026 task extensions, additional multi-round-trip input, and broader compatibility qualification. Supported 2026 form and HTTPS URL input and 2025 form input are user-reviewed and continue only after an explicit response. 2025 server-initiated URL input remains unsupported. OAuth supports pre-registered and dynamically registered public clients; an Agentnik-hosted client metadata document and real-provider qualification remain. Task elicitation, broader content types and expanded Chat support need separate design and tests. Experimental task-required execution on local and remote servers waits for a final result within the operation deadline; a stopped task may continue on its server. Keep server output and skill instructions untrusted, bound resources and credentials, and preserve the current disclosed MCP permissions. Skills never grant permissions by themselves.
5. **Spec & Plan interoperability.** Keep Agentnik's documented track format and user-reviewed reconciliation. Any future Conductor support starts with a read-only adapter and fixtures from a pinned upstream revision; import/export or writes require lossless round-trip and conflict tests. Do not claim plugin compatibility from a similar workflow.
6. **Image generation.** Chat and Code have an optional image generation and editing tool using a separately selected connection and model, including OpenRouter and configured compatible passthroughs. Continue qualifying text-model tool calling, end-to-end GUI workflows, image editing, cancellation and additional providers with explicitly authorized tests. Generated images are not automatically inspected by the text model. See [validation](VALIDATION.md) for scoped live observations.
7. **Computer use.** Add an optional, user-directed Code tool for controlling a visible browser, followed by native desktop support. Start with browser navigation, page inspection, screenshots, clicks, typing and scrolling through an Agentnik-owned function-calling interface; consider provider-specific adapters separately. Reuse image input for vision-capable models, and expose page structure where available. Require explicit enablement, show the controlled target and action activity, disclose when screenshots leave the device, and let cancellation or steering stop further actions. Design confirmation for consequential actions, handle focus, display scaling and stale screen state, and never automatically replay uncertain actions. Validate with a fake backend and authorized live browser tasks before qualifying models and platforms; desktop support needs separate OS permission and compatibility testing.
8. **Future enhancements.** Consider goal-wide token limits only with an explicit policy for missing provider usage, estimates and enforcement. Longer test jobs, richer diagnostics, symbol navigation, broader document analysis and stronger process isolation require separate bounded designs.

## Research and safety boundaries

Managed research and hosted search have bounded routing, explicit opt-in and conservative fallback. Preserve public-address checks, provider disclosures, source attribution and access restrictions. Never bypass blocks or infer a provider's support from a model listing. Computer use is a future, user-directed Code capability and is not currently implemented. Arbitrary research execution, autonomous background tasks and automatic provider failover remain outside the current scope.

For each change, inspect the implementation and relevant guide, preserve user data, test meaningful failure and cancellation paths, and distinguish offline mocks, native checks and authorized live evidence. The development and release commands are in [development and builds](DEVELOPMENT_VALIDATION.md).
