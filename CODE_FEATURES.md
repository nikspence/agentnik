# Coding features

## Code: a coding agent for your models

Register a local repository or ordinary folder in **Repositories**, then choose it from **＋ Code**. Each coding pane keeps its own working directory snapshot, task, model assignments, and activity. Removing a repository entry preserves its files and history.

Agentnik runs its own coding loop using your configured connections and models, with no Codex runtime dependency. Select models from the available list or enter an alias manually, including aliases exposed by LiteLLM.

- **Same-model subagents:** the selected Model can delegate two or three concurrent tasks. Each child can inspect approved text and image snapshots and create files in its own assigned output folder; Agentnik publishes successful staged outputs without overwriting existing files. Children do not use shell or web tools or delegate. They share run limits and can be cancelled individually. See [subagents](CODING_GUIDE.md#skills-updates-and-subagents).
- **Goals and steering:** opt in to sustained goal pursuit, pause and explicitly continue it, and send steering messages during a run. Completion is model-reported; inspect its supporting evidence. Activity records steering delivery outcomes.

- **File and shell tools:** inspect and change UTF-8 project files, rename or move regular files of any size or encoding, delete individual files of any size or encoding, and create, rename, or move directories without per-file approval during a coding run. Moves stay within the project and never overwrite existing destinations. File moves support cross-filesystem copies; directory moves require the same filesystem and a safe no-overwrite rename. Activity records the changes. Content edits require a prior read; source metadata changes stop a move or deletion. Shell commands require approval by default; a switch can allow shell and test commands without individual approval before or during a run.
- **Focused project tools:** get a bounded project overview, find filenames with glob patterns, search UTF-8 files for literal text or regular expressions with a glob filter and optional case-insensitivity, read numbered line ranges in files up to 10 MB, and apply exact-match patches to text already read. Search results identify incomplete scans, including regex timeouts. Patches preserve surrounding content and check the file version before applying.
- **Repository guidance:** automatically load root `AGENTS.md` before a coding run and nested rules when tools target their directories. Activity identifies loaded files and scopes. Deeper guidance applies within its subtree; user instructions and approval/security rules take priority. Newly discovered rules defer proposed mutations until the model can review them.
- **Repository Skills:** select up to five repository or user skills from `.agents/skills/<name>/SKILL.md` in the Code pane. User skills come from `~/.agents/skills`; matching names remain separate. Preview instructions before selecting them. Selected instructions are sent to the model when a run starts, with their SHA-256 revision shown in activity and the Skill history dialog; bounded text references can be read on demand. Scripts follow the shell approval switch. Skill frontmatter uses bounded safe YAML parsing. If a selected instruction file changes or disappears, review and reconfirm it in Skills before running; changes during a run stop the run. Older sessions acquire selection hashes when their Skills selection is confirmed.
- **MCP servers:** use **MCP servers** to save local stdio commands or remote HTTPS server URLs and explicitly test them. Remote tests use TLS 1.2 or newer and a bearer token stored in the operating-system credential store, negotiate supported Streamable HTTP protocol versions (2025-03-26, 2025-06-18, or 2025-11-25), complete initialization, and show descriptions and input schemas for up to five pages or 100 tools; local tests keep a stdio session open and discover tools. You can manually call a discovered local or remote tool; tools run without approval, including write-capable tools. For each call, Agentnik checks that its definition has not changed before the call and never retries an uncertain call. Tools requiring MCP task execution cannot be called yet. Arguments are checked against a bounded JSON Schema 2020-12 or declared Draft 7 subset, including local `$defs` or `definitions` references and limited `anyOf`, `oneOf`, and `allOf` combinations. Recursive or external references and unsupported features are rejected. In Code, use **MCP servers…** to check up to five local or remote servers and move them into precedence order; the model can request discovery and tool calls. The first selected server with a matching tool name takes precedence. Selections are remembered per Code session without starting servers when reopened. If a saved server configuration changes or becomes unavailable, reselect or remove it before running. Discovery and supported resource and prompt reads run without approval. MCP tools run without approval, including writes and other external actions. Shell commands follow the separate approval switch. When multiple servers are selected, each request names its server and uses that server’s independent session. Tool metadata and results are untrusted and are sent to the selected model. Protocol errors show a bounded, untrusted server message and code; error data is not included, and a tool call that returns a protocol error may have changed server state. The read-only annotation is a server claim and is not enforced; trust the selected server. Starting a local server runs its program with your user permissions. For servers that advertise resources, Code can list up to five resource pages or 100 resources and read a listed text resource. Resource listings are also capped at 200 KB of metadata and report when more may be available. Code can also list and retrieve MCP prompts containing text or embedded text resources; prompt messages remain untrusted tool results, and user-only content is displayed in activity rather than sent to the model. Code can also list resource templates and read text using scalar URI-template substitutions, including multiple variables and `+`, `#`, `.`, `/`, `;`, `?`, and `&` expressions; scalar prefix modifiers are supported; composite values and explode modifiers remain unsupported. Variables may be supplied as strings; omitted or null variables are undefined and excluded from expansion. Listings and expanded URI reads run without approval. When image inspection is enabled, assistant-directed PNG, JPEG, and WebP images returned by tools are validated and sent to the selected model as untrusted visual input, with at most four images per batch; user-only images are not sent to the model. Other binary resources and non-text prompt content are not yet supported. Local commands and arguments are stored as plaintext; do not put credentials in them. For local servers, **Environment names** accepts a JSON mapping such as `{"SERVER_TOKEN":"MY_EXISTING_TOKEN"}`: Agentnik reads the value of `MY_EXISTING_TOKEN` from its own environment and passes it to the server as `SERVER_TOKEN`. Only names are saved. Restart Agentnik after changing its environment; mapped values are captured for each coding run and treated as sensitive, and responses containing them are blocked. Local servers also inherit Agentnik’s environment. Local sessions answer bounded server-initiated ping requests and reject unsupported server requests. They remain open while the server is selected, allowing connection-oriented tools to work; closing the dialog or selecting another server ends the session. On Windows, Agentnik assigns the server process to a job object and closes the job on shutdown to terminate contained children. Processes started before assignment or allowed to break away may escape; other platforms currently terminate only the direct process. On Windows, `npx` uses the installed Node.js npm CLI. Coding runs keep remote HTTP sessions open across calls when the server issues a session ID; tool definitions are checked again before each call, and Agentnik attempts to close the session at the end. Manual remote calls use separate sessions. SSE parsing accepts standard LF, CRLF and CR line endings, priming events, and multiline data; incomplete events are rejected. HTTP stream resumption, server-initiated HTTP requests, and unsolicited server notifications are not supported. OAuth is not yet supported.

  Tool discovery allows up to 131,072 bytes per local JSON-RPC message or HTTP response, including each page and tool-definition recheck. Tool-call responses allow up to 1,048,576 bytes; other MCP responses remain limited to 65,536 bytes. Code and Chat also apply their configured shared context budgets, so a large result may exceed the remaining run budget. Separate limits apply to individual descriptions and schemas, total retained metadata, page count and tool count.

  Each server has an **Operation timeout** in MCP servers, from 1 to 900 seconds; the default for existing and new profiles is 60 seconds. It covers the complete operation, including discovery or rechecking definitions and the server response. Code's overall run deadline can stop it sooner; remote session shutdown remains separately bounded. A timed-out call may have completed on the server and is not replayed automatically. Changing the timeout changes the saved server configuration, so reselect it in existing Code sessions.

  To test a local server, save and select its profile, then choose **Test connection**. The Arguments field is JSON: on Windows use forward slashes, for example `["D:/dev/my-server/server.py"]`, or escape each backslash. Use the full path to the Python interpreter that has the server's dependencies installed. Unsaved edits must be saved before testing, so the reviewed command matches the editor.

  Local stdio profiles can optionally set an absolute **Working directory** for servers that use relative paths. A blank field keeps the inherited Agentnik working directory, preserving existing profiles. The directory appears in the server configuration; changes require reselecting the server in an existing Code session. The configured directory must exist when the server starts.

  When a manual HTTPS operation fails after establishing a session, Agentnik attempts a bounded session close and retains the original error and any uncertain-call warning. If the server does not confirm closure, the manager says so. Closing the session does not establish whether a tool call completed or undo its effects.

  When a tool declares an output schema, discovery and call reviews show it, and changing it invalidates the reviewed definition. Successful structured results are checked against the same bounded JSON Schema subset as tool inputs before Code forwards or caches them. The manual manager validates in a background worker and displays a warning alongside an invalid result. Missing, invalid, or unsupported structured output is not proof that the server did nothing; inspect server state before retrying. Tool-reported errors remain available without requiring successful structured output. Oversized output schemas prevent calls.

  Code respects content-block audience annotations: blocks explicitly intended only for the user are omitted from model tool results. User-directed text appears in Code activity as a bounded excerpt, and user-directed non-text blocks are counted without displaying their contents. The manual manager displays the complete untrusted result. Audience annotations are supplied by the server and apply only to their individual blocks; the same information could also appear in other blocks, structured output, or metadata.

- **Task plans:** The model can maintain a checklist with pending, in-progress, completed, and blocked steps. A collapsible panel shows progress and retains unfinished plans after cancellation or reopening. A new coding run starts a fresh plan.
- **Coding context compaction:** inspect and edit the previous task and answer or its summary; compact manually or automatically before a follow-up run. The full model and tool exchange is not retained between coding runs.
- **Spec & Plan:** inspect and select versioned project tracks for reviewed coding runs, with separate model-reported progress keyed by task ID. Reconcile that report through user-selected statuses and evidence with a revision-bound file diff approval. Draft creation and existing-track edits require individual file approvals; the model can propose drafts without tool access. Conductor compatibility is not implemented.
- **Project memory:** search and read locally stored, project-scoped entries on demand across coding sessions. Inspect, edit, and delete entries in the manager; model-requested additions and updates are saved without an approval prompt and appear in activity. Memory can be stale and does not override user instructions or repository guidance.
- **Document outlines:** locate Markdown headings and JSON/YAML key paths without sending complete documents. Output is bounded; YAML aliases and complex keys are not expanded.
- **Code symbol outlines:** locate Python, JavaScript, JSX, TypeScript, TSX, Go, Rust, C# and Java declarations by line range without executing project code, then read just the relevant file section. Results are bounded and do not authorize edits.
- **Working notes and artifacts:** named, editable session notes preserve concise findings; large shell and test outputs receive temporary run-local references that the model can search or read in ranges. The latest test report and individual parsed failures are retrievable during the run.
- **Structured test results:** submit a test command under the shell approval setting and get reported counts and failure excerpts from unittest, pytest, Jest, or Vitest output. Unrecognized or truncated output stays explicitly uncertain; tests are never launched just by opening a project.
- **Structured Git tools:** inspect tracked status, working and staged file diffs, recent commits, local branches and remote-tracking refs without shell commands. Compare local branch histories for ahead/behind or divergence, list changed paths and inspect individual committed text diffs; tracking refs may be stale. Stage or unstage explicit files, create a branch without switching, and commit selected working files or the reviewed staged snapshot. Fetch and push previews handle one branch on an HTTPS remote with destination and exact-commit approvals; optionally enter a username and token or save the token in the OS credential store for the exact destination and username. Push allows new branches and verified fast-forwards only. Each mutation requires approval; commits display the full diff, message, identity, and parent. Unstaging and staged commits preserve working-file edits. Local commit tools require an existing repository with a commit and configured Git identity; hooks and signing are disabled. Fetch and push have offline test coverage; live HTTPS and authentication compatibility remain outstanding.
- **Research while coding:** enable the global **Web** switch to look up APIs, read documentation, and follow discovered public documentation links as part of the task. Sources and excerpts appear in the run activity and Sources view.
- **Context usage tool:** The model can inspect content-free request-size estimates, reported input tokens when available, and shared run budgets without conflating bytes with the model context window.
- **Adjustable run limits:** **Settings → Code and goal limits…** controls loop rounds, model requests, tool calls, total elapsed time, model call timeout, and continuation context. Model calls default to 300 seconds; new runs default to 3,600 seconds overall. The model, subagents, and research share the run budget.
- **Compact workflow controls:** Choose the Model at the top of the Code pane; configure the optional Decision assignment in Settings. Approval controls appear when a proposal needs review. Optionally include the bounded previous task and answer in a follow-up.
- **Code activity:** output follows the bottom while you are reading the latest activity. Scroll up to pause following and return to the bottom to resume. Up to 10,000 entries and 4 million text characters are retained per coding session; oldest entries are trimmed when either limit is reached.
- **Prompt history:** use the arrows beside the coding prompt or Up/Down at the first or last line to revisit submitted prompts. Each coding session keeps its own history and preserves the current draft while browsing.
- **Prompt attachments:** attach images and locally reviewed documents to a coding draft. The initial model request receives extracted document text and images, including optional PDF page images. Draft attachments persist with the session; image support depends on the selected model and endpoint.
- **Git remote inspection:** the coding agent can list remote names and configured fetch/push transport types from the repository's local Git configuration without contacting a remote. URLs, including their credentials and paths, are not sent to the model. Includes and URL rewrites are not resolved, so this does not establish the effective destination.
- **Cancellation and persistence:** cancel retains your draft and project changes already applied. Reopening a saved coding session never restarts execution.

Approved shell commands run with your operating-system account's permissions, including network access and paths outside the project. They can run Git commands; the executor is not an operating-system sandbox. File contents and delegated context are sent to the selected model endpoints.

### Optional Decision advice for shell approvals

Choose a compatible System One Decision connection and model, then enable **Check shell approvals with Decision model** in Settings. Agentnik sends the exact proposed command, working directory, shell, and environment variable names (excluding their values) to that endpoint.

The approval view shows **SAFE**, **WARNING**, **RISKY**, **PRIVACY**, or **DANGER**, with confidence when supplied. Failed, invalid, or timed-out checks show **UNKNOWN**. The category guide explains the recommendation; you approve or reject commands when approval is required; commands allowed by the switch do not request advice. Advice currently covers shell commands, and compatibility with a real decision model remains unverified for this integration.
