# Coding features

## Code: a coding agent for your models

Register a local repository or ordinary folder in **Repositories**, then choose it from **＋ Code**. Each coding pane keeps its own working directory snapshot, task, model assignments, and activity. Removing a repository entry preserves its files and history.

Agentnik runs its own coding loop using your configured connections and models, with no Codex runtime dependency. Select models from the available list or enter an alias manually, including aliases exposed by LiteLLM.

- **Heavy and Light delegation:** Heavy leads the task, inspects the project, and proposes changes. Enable **Allow light model delegation** to let it delegate bounded routine analysis to a separately selected Light model within the same workflow. The roles can use different connections and providers. Heavy can also request two or three concurrent analysis tasks using Light and up to two optional alternate subagent models. Heavy chooses the role per task; alternates can also be chosen for independent document reviews, but are not automatic fallbacks. Each requested project file is reviewed and approved separately before it is sent to the selected endpoint. For a parallel task, Heavy may enable read, glob and literal grep tools over only that child’s approved snapshots (up to eight files, 8 KB each); no other project files or write, shell, network or delegation tools are available to the child. Approved snapshots are also supplied in the initial context. If a model explicitly rejects tool calling before producing a response, Agentnik retries once without tools using that same context; other failures are not retried. Confirmed rejections are remembered by endpoint, protocol and model (and saved connection identity where available), so future runs start without tools. Use **Forget remembered subagent tool support** in Models to try again after an upgrade. Each child has at most three inspection rounds and eight tool calls, sharing the run budgets. Activity shows results as they finish, with elapsed time and reported token usage.
The Code pane shows a collapsible Subagents view with the latest status and bounded findings for up to 32 children in the current real coding run. Select an active child and choose **Cancel subagent** to stop waiting for that child while its siblings continue. Heavy receives a cancelled result without the child’s late output. An identical task and file scope cannot be retried or reassigned during the same run; changed wording still depends on model compliance. Cancelled and interrupted children remain visible; reopening never resumes work. Starting a new run clears the prior view. Cancellation stops waiting and scheduling; a request already submitted to a model endpoint may continue remotely.

- **Independent document review:** ask Heavy for a comprehension, requirements, design, or implementation-readiness review with Light delegation enabled. Each review uses a fixed role and one project text file (up to 8 KB) with a configured Light or alternate model. Requirements, design and readiness reviews can include up to three explicitly approved project evidence files (8 KB each). The approval view shows the complete instructions, document and evidence, destination, and hashes. Approve each request or reject it to skip. Reviews run one at a time; each fresh request excludes the drafting conversation, earlier findings, selected Skills and project guidance, and the reviewer has no tools. Findings, failures and cancellation appear in Subagents and activity. If the document or evidence changes during a review, its findings are discarded. Findings are untrusted suggestions; a provider may retain its own context, and later file changes are not monitored.

- **File and shell tools:** inspect and change UTF-8 project files, rename or move regular files of any size or encoding, delete individual files of any size or encoding, and create, rename, or move directories without per-file approval during a coding run. Moves stay within the project and never overwrite existing destinations. File moves support cross-filesystem copies; directory moves require the same filesystem and a safe no-overwrite rename. Activity records the changes. Content edits require a prior read; source metadata changes stop a move or deletion. Shell commands require approval.
- **Focused project tools:** get a bounded project overview, find filenames with glob patterns, search UTF-8 files for literal text or regular expressions with a glob filter and optional case-insensitivity, read numbered line ranges in files up to 10 MB, and apply exact-match patches to text already read. Search results identify incomplete scans, including regex timeouts. Patches preserve surrounding content and check the file version before applying.
- **Repository guidance:** automatically load root `AGENTS.md` before a coding run and nested rules when tools target their directories. Activity identifies loaded files and scopes. Deeper guidance applies within its subtree; user instructions and approval/security rules take priority. Newly discovered rules defer proposed mutations until the model can review them.
- **Repository Skills:** select up to five repository or user skills from `.agents/skills/<name>/SKILL.md` in the Code pane. User skills come from `~/.agents/skills`; matching names remain separate. Preview instructions before selecting them. Selected instructions are sent to the model when a run starts, with their SHA-256 revision shown in activity and the Skill history dialog; bounded text references can be read on demand. Scripts still require command approval. Skill frontmatter uses bounded safe YAML parsing. If a selected instruction file changes or disappears, review and reconfirm it in Skills before running; changes during a run stop the run. Older sessions acquire selection hashes when their Skills selection is confirmed.
- **MCP servers:** use **MCP servers** to save local stdio commands or remote HTTPS server URLs and explicitly test them. Remote tests use a bearer token stored in the operating-system credential store, negotiate supported Streamable HTTP protocol versions (2025-03-26, 2025-06-18, or 2025-11-25), complete initialization, and show descriptions and input schemas for up to five pages or 100 tools; local tests keep a stdio session open and discover tools. You can manually call a discovered local or remote tool; tools run without approval, including write-capable tools. For each call, Agentnik checks that its definition has not changed before the call and never retries an uncertain call. Tools requiring MCP task execution cannot be called yet. Arguments are checked against a bounded JSON Schema 2020-12 or declared Draft 7 subset, including local `$defs` or `definitions` references and limited `anyOf`, `oneOf`, and `allOf` combinations. Recursive or external references and unsupported features are rejected. In Code, select up to five enabled local or remote servers for a run; the model can request discovery and tool calls. Selections are remembered per Code session without starting servers when reopened. If a saved server configuration changes or becomes unavailable, reselect or remove it before running. Discovery and supported resource and prompt reads run without approval. MCP tools run without approval, including writes and other external actions. Shell commands still require approval. When multiple servers are selected, each request names its server and uses that server’s independent session. Tool metadata and results are untrusted and are sent to the selected model. Protocol errors show a bounded, untrusted server message and code; error data is not included, and a tool call that returns a protocol error may have changed server state. The read-only annotation is a server claim and is not enforced; trust the selected server. Starting a local server runs its program with your user permissions. For servers that advertise resources, Code can list up to five resource pages or 100 resources and read a listed text resource. Resource listings are also capped at 200 KB of metadata and report when more may be available. Code can also list and retrieve text-only MCP prompts; prompt messages remain untrusted tool results. Code can also list resource templates and read text using scalar URI-template substitutions, including multiple variables and `/`, `?`, and `&` expressions; other URI-template forms are shown as unsupported. Variables may be supplied as strings; omitted or null variables are undefined and excluded from expansion. Listings and expanded URI reads run without approval. Binary resources and non-text prompt content are not yet supported. Local commands and arguments are stored as plaintext; do not put credentials in them. For local servers, **Environment names** accepts a JSON mapping such as `{"SERVER_TOKEN":"MY_EXISTING_TOKEN"}`: Agentnik reads the value of `MY_EXISTING_TOKEN` from its own environment and passes it to the server as `SERVER_TOKEN`. Only names are saved. Restart Agentnik after changing its environment; mapped values are captured for each coding run and treated as sensitive, and responses containing them are blocked. Local servers also inherit Agentnik’s environment. Local sessions answer bounded server-initiated ping requests and reject unsupported server requests. They remain open while the server is selected, allowing connection-oriented tools to work; closing the dialog or selecting another server ends the session. On Windows, Agentnik assigns the server process to a job object and closes the job on shutdown to terminate contained children. Processes started before assignment or allowed to break away may escape; other platforms currently terminate only the direct process. On Windows, `npx` uses the installed Node.js npm CLI. Coding runs keep remote HTTP sessions open across calls when the server issues a session ID; tool definitions are checked again before each call, and Agentnik attempts to close the session at the end. Manual remote calls use separate sessions. SSE parsing accepts standard LF, CRLF and CR line endings, priming events, and multiline data; incomplete events are rejected. HTTP stream resumption, server-initiated HTTP requests, and unsolicited server notifications are not supported. OAuth is not yet supported.

  Each server has an **Operation timeout** in MCP servers, from 1 to 900 seconds; the default for existing and new profiles is 60 seconds. It covers the complete operation, including discovery or rechecking definitions and the server response. Code's overall run deadline can stop it sooner; remote session shutdown remains separately bounded. A timed-out call may have completed on the server and is not replayed automatically. Changing the timeout changes the saved server configuration, so reselect it in existing Code sessions.

  To test a local server, save and select its profile, then choose **Test connection**. The Arguments field is JSON: on Windows use forward slashes, for example `["D:/dev/my-server/server.py"]`, or escape each backslash. Use the full path to the Python interpreter that has the server's dependencies installed. Unsaved edits must be saved before testing, so the reviewed command matches the editor.

  Local stdio profiles can optionally set an absolute **Working directory** for servers that use relative paths. A blank field keeps the inherited Agentnik working directory, preserving existing profiles. The directory appears in the server configuration; changes require reselecting the server in an existing Code session. The configured directory must exist when the server starts.

  When a manual HTTPS operation fails after establishing a session, Agentnik attempts a bounded session close and retains the original error and any uncertain-call warning. If the server does not confirm closure, the manager says so. Closing the session does not establish whether a tool call completed or undo its effects.

  When a tool declares an output schema, discovery and call reviews show it, and changing it invalidates the reviewed definition. Successful structured results are checked against the same bounded JSON Schema subset as tool inputs before Code forwards or caches them. The manual manager validates in a background worker and displays a warning alongside an invalid result. Missing, invalid, or unsupported structured output is not proof that the server did nothing; inspect server state before retrying. Tool-reported errors remain available without requiring successful structured output. Oversized output schemas prevent calls.

  Code respects content-block audience annotations: blocks explicitly intended only for the user are omitted from model tool results. User-directed text appears in Code activity as a bounded excerpt, and user-directed non-text blocks are counted without displaying their contents. The manual manager displays the complete untrusted result. Audience annotations are supplied by the server and apply only to their individual blocks; the same information could also appear in other blocks, structured output, or metadata.

- **Task plans:** Heavy can maintain a checklist with pending, in-progress, completed, and blocked steps. A collapsible panel shows progress and retains unfinished plans after cancellation or reopening. A new coding run starts a fresh plan.
- **Coding context compaction:** inspect and edit the previous task and answer or its summary; compact manually or automatically before a follow-up run. The full model and tool exchange is not retained between coding runs.
- **Project memory:** search and read locally stored, project-scoped entries on demand across coding sessions. Inspect, edit, and delete entries in the manager; model-proposed additions and updates require approval. Memory can be stale and does not override user instructions or repository guidance.
- **Document outlines:** locate Markdown headings and JSON/YAML key paths without sending complete documents. Output is bounded; YAML aliases and complex keys are not expanded.
- **Code symbol outlines:** locate Python, JavaScript, JSX, TypeScript, TSX, Go and Rust declarations by line range without executing project code, then read just the relevant file section. Results are bounded and do not authorize edits.
- **Working notes and artifacts:** named, editable session notes preserve concise findings; large shell and test outputs receive temporary run-local references that the model can search or read in ranges. The latest test report and individual parsed failures are retrievable during the run.
- **Structured test results:** submit an approved test command and get reported counts and failure excerpts from unittest, pytest, Jest, or Vitest output. Unrecognized or truncated output stays explicitly uncertain; tests are never launched just by opening a project.
- **Structured Git tools:** inspect tracked status, working and staged file diffs, recent commits, and local branches without shell commands. Stage or unstage explicit files, create a branch without switching, and commit selected working files or the reviewed staged snapshot. Each mutation requires approval; commits display the full diff, message, identity, and parent. Unstaging and staged commits preserve working-file edits. These local Git tools require an existing repository with a commit and configured Git identity; hooks and signing are disabled. Remote Git tools remain planned.
- **Research while coding:** enable **Allow web research** to look up APIs, read documentation, and follow discovered public documentation links as part of the task. Sources and excerpts appear in the run activity and Sources view.
- **Adjustable run limits:** the **Limits…** dialog controls loop rounds, model requests, tool calls, total elapsed time, model call timeout, and continuation context. Model calls default to 300 seconds; new runs default to 3,600 seconds overall. Heavy, Light, and research share the run budget.
- **Compact workflow controls:** Run and Cancel sit above a collapsible Models panel containing Heavy, Light, and Decision assignments. Approval controls appear when a proposal needs review. Optionally include the bounded previous task and answer in a follow-up.
- **Code activity:** output follows the bottom while you are reading the latest activity. Scroll up to pause following and return to the bottom to resume. Up to 10,000 entries and 4 million text characters are retained per coding session; oldest entries are trimmed when either limit is reached.
- **Prompt history:** use the arrows beside the coding prompt or Up/Down at the first or last line to revisit submitted prompts. Each coding session keeps its own history and preserves the current draft while browsing.
- **Cancellation and persistence:** cancel retains your draft and project changes already applied. Reopening a saved coding session never restarts execution.

Approved shell commands run with your operating-system account's permissions, including network access and paths outside the project. They can run Git commands; the executor is not an operating-system sandbox. File contents and delegated context are sent to the selected model endpoints.

### Optional Decision advice for shell approvals

Choose a compatible System One Decision connection and model, then enable **Check shell approvals with Decision model** in Models. Agentnik sends the exact proposed command, working directory, shell, and environment variable names (excluding their values) to that endpoint.

The approval view shows **SAFE**, **WARNING**, **RISKY**, **PRIVACY**, or **DANGER**, with confidence when supplied. Failed, invalid, or timed-out checks show **UNKNOWN**. The category guide explains the recommendation; you still approve or reject every command. Advice currently covers shell commands, and compatibility with a real decision model remains unverified for this integration.
