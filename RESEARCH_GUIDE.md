# Research guide

## Research: web access for models that need it

Agentnik-managed research gives tool-capable models access to search and public page retrieval even when they have no built-in browsing service. The selected model requests a tool; Agentnik retrieves bounded evidence and returns it to the model. Research is opt-in. Model listings do not establish compatibility; explicit unsupported responses are remembered.

**Chat research** supports managed tools across native Ollama, Responses, Chat Completions, and Messages. Compatible models on the official OpenAI Responses endpoint can also use provider-hosted web search. Choose **Provider first** (the default) or **Agentnik first** under **Settings → Search priority**; the preference applies across Chat and Code. Eligible fallback is visible in activity and retains your model and connection. Global search settings support up to five ordered, independently credentialed backend profiles.

Turn on **Web** in the toolbar for new Chat and Code runs. Set the global search priority and navigation policy in **Settings**. Chat always offers local calculator and data-analysis tools, including with web research and MCP. No per-model enablement is required. When an MCP server is selected and conflict priority is MCP First, Agentnik uses managed search so it can enforce MCP name precedence. Explicit provider-hosted unsupported responses are remembered for the affected model and connection; future runs use managed search.

**Managed search providers:** configure **Brave Search**, **LangSearch**, **Firecrawl**, **Exa**, or **Parallel** in **Settings → Search providers…**. Choose a provider, enter its separate API key when required, and order your profiles. **Firecrawl (keyless)** requires no account key. These providers work across supported model connections, including local models and LiteLLM, when the model can call research tools. Exa uses `auto` search with highlights; Parallel uses `basic` search with bounded excerpts. Provider search/content charges may apply. Keys use the OS credential store with explicit plaintext fallback. Alternatively set `BRAVE_SEARCH_API_KEY`, `LANGSEARCH_API_KEY`, `FIRECRAWL_API_KEY`, `EXA_API_KEY`, or `PARALLEL_API_KEY`; environment profiles follow saved profiles within the five-profile limit. See the [search provider guide](SEARCH_PROVIDERS.md) for setup, API scope, validation, and Exa/Parallel search modes.

**Coding research** uses provider-hosted search first on eligible official OpenAI Responses connections when that priority is selected. Explicit unsupported responses fall back to managed search before any partial work. Managed search uses your configured profiles and direct public page reads. Ollama search profiles remain eligible only for direct Ollama Cloud coding connections; an Ollama model through LiteLLM uses the other managed providers. Configured search providers run first, followed by **Firecrawl Keyless**, then **Google scrape** after eligible failures. With no provider configured, Firecrawl Keyless is the default. Fallback is visible in research activity and stops on access restrictions, timeouts, cancellation, or uncertain outcomes. Google can still be rate-limited or challenged. Direct page retrieval can read known URLs without a search key.

In Code, if an MCP `web_fetch` for public URLs is explicitly unavailable or returns an eligible error, Agentnik can use managed page retrieval instead when Web is enabled. For Parallel URL lists, successful MCP results are retained and only eligible failed URLs are fetched; requests explicitly limited to cached content do not trigger live fetching. A completed MCP response rejected by output-schema validation can also fall back when its content does not indicate an access restriction. Access restrictions, timeouts, cancellation and uncertain outcomes do not trigger this fallback.

Public page retrieval requires no search key and can read a known documentation URL directly. Direct reads and provider connections verify TLS certificates and hostnames by default; the global TLS setting can relax both for TLS-inspecting networks. Relaxing verification lets an intermediary impersonate a site or alter content; treat retrieved text as untrusted. URL, DNS, and redirect checks reject private/local destinations, embedded credentials, and ports outside 80/443. Direct page requests send no provider credentials, search keys, cookies, or proxies. Strict public-only navigation disables external search while retaining permitted public page reads.

If a direct page read is recognized as a network-filter block (such as a Zscaler block page), or encounters an eligible connection, TLS, or HTTP failure, Agentnik can ask a configured retrieval-capable provider to read the public URL. Keyed Firecrawl, Exa, Parallel, and eligible Ollama profiles support this; Firecrawl Keyless is not used for page-fetch fallback. The URL is disclosed to that service, provider navigation is external, and charges may apply. Activity identifies the fallback and returned source. Private destinations/redirects, generic site access denials, timeouts, cancellation, and strict public-only navigation do not use this fallback. No browser login, cookies, or local proxy credentials are forwarded.

Brave search omits individual results that fail public-address checks while retaining safe results. If a search is blocked by an access restriction during a coding run, Agentnik stops further searches for that run and lets the model continue with existing sources; activity identifies HTTP status when available.

Successful managed search results are cached in memory for 30 minutes and can be reused by a later run with the same query, backend profile, and result limits. In Code, MCP tools whose names contain `search`, advertise the read-only hint, and accept a `query` string also reuse successful results for identical server, tool, and arguments after approval and a fresh tool-definition check. Cache entries are scoped to the server identity and credential context. The cache is bounded and cleared when Agentnik exits; failures are not cached. Provider-hosted searches cannot be cached by Agentnik.

Research activity exposes searches, page reads, route/backend choices, recovery, errors, sources, and excerpts. Public HTML pages are converted to structured text with Markdown headings, links, lists and code where possible, preferring main or article content. This is a best-effort extraction of downloaded HTML; JavaScript is not executed and page structure may be incomplete. Public page reads are bounded: if a page exceeds the per-page download limit, Agentnik returns the available prefix as a source marked truncated instead of ending the run. Extracted page excerpts are limited to 32,000 UTF-8 bytes and may omit later content; consult linked or narrower pages when necessary. The combined retrieval budget is 12 MB per research turn or Code goal step. Chat supports clickable provider citations and validated managed `[S1]` references. Retrieved text and search results are untrusted evidence; a source link alone does not establish that a claim is correct. Requests, tool rounds, bytes, context, retries, and time are bounded. Partial or ambiguous failures do not silently replay inference.

Use **Settings → Chat research limits…** to adjust its tool rounds, calls, model requests, search results, research context, request timeout, and total turn time. These limits apply globally to new Chat runs and are shared by their research route attempts. Defaults allow 48 tool rounds, 96 calls, 50 model requests, 5 results per search, 2,000,000 bytes of research context, 600 seconds per request, and 3,600 seconds per turn. Previously saved per-chat limits remain in history but are no longer used. The request timeout includes both waiting for the first token and generating the full response; the turn deadline can stop it sooner. Larger limits can increase time and provider charges. When a managed run reaches a round, call, or model-request limit after gathering results, Agentnik asks the model for a final answer without further tools. Other limits, cancellation, and uncertain failures can still stop the run before synthesis; partial evidence is retained.

If a later tool-call batch would exceed the remaining call budget, Agentnik skips the entire batch and asks for a final answer using the evidence already collected, when another model request is available. Activity shows the skipped calls. Invalid calls and credential-bearing arguments remain errors, and no part of an oversized batch is executed.

Search queries can contain information derived from your task. Inference credentials are not reused as search credentials; configured search keys use the credential store with explicit plaintext fallback. Research remains a preview with observed compatibility for specific models and routes in [VALIDATION.md](VALIDATION.md).
