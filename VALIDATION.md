# Validation and compatibility

The automated suite uses mocked endpoints, temporary data and offscreen Qt. It does not establish live model or platform compatibility. See [development and builds](DEVELOPMENT_VALIDATION.md) for commands and optional live checks; ordinary tests do not issue inference requests.

## Scoped observations

- The build-only `0.12.0rc3` distributions from `9b48efa` matched their recorded SHA-256 checksums. The downloaded wheel passed 81 terminal tests outside the checkout in a fresh Qt-free Windows environment, with two POSIX-only skips. The installed wheel also passed the Windows ConPTY keyboard and transcript recovery check. No PyPI publication was requested. [rc3 preview](https://github.com/nikspence/agentnik/actions/runs/45891736121)

- The build-only `0.12.0rc2` distributions from `f3e9ac4` matched their recorded SHA-256 checksums. On Windows Python 3.11, installing the downloaded wheel over `rc1` updated the launcher version and preserved saved connection settings in a disposable profile. The upgraded install had no Qt and passed 75 terminal tests, with two POSIX-only skips. The downloaded wheel also passed the Linux OpenSSH fixture, and all four hosted Qt-free jobs passed, including Windows and macOS draft cancellation. The publish job was skipped. [rc2 preview](https://github.com/nikspence/agentnik/actions/runs/45888132513) · [Hosted wheel checks](https://github.com/nikspence/agentnik/actions/runs/45888131506)

- The build-only `0.12.0rc1` distributions from `35d04f6` matched their recorded SHA-256 checksums. The downloaded wheel passed 73 terminal tests outside the checkout in a fresh Windows Python 3.11 environment without Qt, with one POSIX-only skip. All four hosted Qt-free jobs passed at `760ccd7`, which has the same application code as that build. No preview was published to PyPI by these runs. [Current preview build](https://github.com/nikspence/agentnik/actions/runs/45886609435) · [Hosted wheel checks](https://github.com/nikspence/agentnik/actions/runs/45886458751)

- The hosted Windows ConPTY and macOS PTY tests exercise Ctrl+J multiline entry, Enter submission, and Up history recall. Windows also checks Down draft restoration. A separate Windows ConPTY probe reopened a synthetic session, opened `/transcript`, returned with Q, and ran `/status`. These checks use simulated inputs and do not qualify physical keyboards or terminal-emulator shortcuts. [Windows keyboard check](https://github.com/nikspence/agentnik/actions/runs/45881288143) · [macOS keyboard check](https://github.com/nikspence/agentnik/actions/runs/45882967881)

- Local keyboard smoke tests at `0261c7b` (Ubuntu PTY under WSL) and `41ef282` (Windows ConPTY) verified that Ctrl+T opens the transcript, Ctrl+U moves back, and Q returns to an unchanged draft that Enter submits. These runs used the checkout and simulated input, not a physical keyboard or terminal emulator. The same scrollback workflow passed against the installed Qt-free wheel on hosted Windows, macOS and Ubuntu (Python 3.11) at `e1baf2f`. [Hosted keyboard checks](https://github.com/nikspence/agentnik/actions/runs/45890674049) · [Native keyboard check](DEVELOPMENT_VALIDATION.md#native-terminal-keyboard-check)

- The installed preview passed loopback OpenSSH with a fresh non-root account and a local model fixture. The check covers connection setup, an approved edit, Ctrl+C while a response is withheld, and resume without replay. A local run also verified credential-free connection transfer to a new profile. The [reproduction guide](DEVELOPMENT_VALIDATION.md#qt-free-ssh-smoke-test) covers the disposable environment. These results do not establish live-provider behavior over SSH or server-side cancellation. [Hosted SSH check](https://github.com/nikspence/agentnik/actions/runs/45882769651)

- The expanded SSH fixture at `a32b798` passed locally against the downloaded `rc2` wheel and on hosted Ubuntu. It verified that an out-of-project folder was created only after approval and that the next task after resume did not expose the machine creation tool. A local run at `d3ed18d` also verified the no-echo credential prompt and explicit fallback consent with the OS credential store deliberately unavailable. [Hosted SSH run](https://github.com/nikspence/agentnik/actions/runs/45888747297)

- At `760ccd7`, all 140 coding-engine tests passed on Windows, and 73 terminal tests passed under Linux on WSL, with the Windows-only test skipped.

- Machine-scope terminal tests passed on native Windows and on Linux under WSL at `37b2ce0` (56 and 55 passing respectively, with the Windows-only path test skipped on Linux). Mocked requests verified absolute-path reads and writes, a declined write leaving no file, return to project scope on resume, and rejection of a machine tool call after resume. This does not qualify macOS or live model behavior.

- A live terminal Code run with scripted input on Windows used GPT-6.1 Terra through OpenRouter Chat Completions to call `view_image` on a synthetic 16:9 PNG. The first request contained no image. The continuation carried the PNG and correctly identified both shapes and their positions. This qualifies inspection for that model and route, not live image generation or the full presentation-skill workflow.

- The terminal image workflow test at `6fc7ab1` used distinct mocked connections for generation and coding. It verified an approved image was written to the project and supplied to the coding model only on `view_image`. After `/vision off`, the tool disappeared and a forced inspection call sent no image bytes.

- At `760ccd7`, all seven hosted jobs passed. The full offline suite ran on Windows, macOS, and Ubuntu with Python 3.12, alongside the Qt-free installed-wheel checks. Attachment tests cover PDF text extraction, not OCR or page rendering. [Hosted checks](https://github.com/nikspence/agentnik/actions/runs/45886458751)

- The build-only `0.12.0rc1` artifact from `d4ebe7f` includes terminal MCP OAuth client registration. Both downloaded distributions matched the recorded SHA-256 checksums. The wheel launched in a fresh Windows Python 3.11 environment without Qt, and all four hosted Qt-free jobs passed. The publish job was skipped. [Build-only artifact](https://github.com/nikspence/agentnik/actions/runs/45877438432) · [Hosted checks](https://github.com/nikspence/agentnik/actions/runs/45877393749)

- Terminal MCP OAuth sign-in tests used a loopback callback and mocked issuer responses to verify both pre-registered and dynamically registered clients. Failed or incompatible registration responses did not trigger a retry or continue to browser authorization. Live issuer registration over SSH remains unqualified.

- On Windows, a live terminal Code smoke test used OpenRouter GPT-6.1 Terra over streaming Chat Completions. With scripted prompt input in a temporary non-Git folder, the model proposed one file edit, waited for approval, wrote the expected bytes, and returned a final answer after two provider requests. The saved session reopened without replay. This qualifies that coding path, not native keyboard behavior, SSH, or LiteLLM.
- A separate Windows terminal Code smoke test used GPT-6.1 Terra through the G-Chat LiteLLM connection configured for Responses. Its catalog was reachable, the model proposed and completed one approved file write with the expected bytes, and it returned a final answer after two requests. Reopening the same session sent no provider request. Prompts were scripted and data was temporary, so this does not qualify native keyboard or SSH behavior.

- Selected Code, Chat and research tasks have completed through local Ollama, OpenRouter and LiteLLM routes. These observations cover individual models and tasks, not all tools or providers.
- OpenRouter and the configured LiteLLM image passthrough have generated and edited images. A live Code model inspected an image, and live subagents created sample slide files; the complete editable PowerPoint workflow remains unqualified.
- On Windows, the optional SDK smoke test passed against MCP Python SDK 2.3.0 using protocol 2025-11-25 over stdio and verified loopback HTTPS: discovery, a synthetic structured tool call, standalone and request-scoped server pings, a resource and template read, prompt retrieval and HTTPS session shutdown. In a separate HTTPS cancellation test, the server received a notification with the matching request ID and its synthetic operation ended. The HTTPS server enforced TLS 1.2 or newer and its temporary certificate was trusted only within the test process. Separate HTTPS tests confirmed response-stream resumption without repeating the synthetic call, and standalone-stream reconnection with replay of a notification sent during disconnection. Offline HTTP fixtures also check duplicate notification handling. Loopback HTTPS fixtures checked OAuth metadata discovery, an internal PKCE authorization-code exchange and refresh-token rotation. Synthetic settings-to-MCP sign-in flows, including dynamic client registration, were checked over loopback HTTPS with a simulated browser callback and mocked credential store. External OAuth providers, tasks, third-party servers, Internet deployment and model behavior remain unqualified.
- Windows clean-machine testing was reported complete, but its build and workflow scope were not specified. Each release's `BUILD-MANIFEST.json` records its build-host smoke result; that is not a separate clean-machine qualification.
